# 版本路线与发布门槛

这里是能力顺序，不是发布日期承诺。持续维护依靠可复现构建、问题记录与回归验收；不默认启用后台定时维护。

## 当前：0.1.0-alpha.1

- 已实现单人窗口、章节列表、任务详情、前置、手动/物品/技能判定、追踪及原生存档数据。
- 已提供独立 Core、两个任务包、构建器、校验器、Lua 测试和安装工具。
- 物资奖励、图形任务树、模组专用适配器、联机和工坊发行仍未实现。
- 实际游戏验收结果见 TESTING.md。

## v0.1.0：单人闭环 alpha

目标：只启用 Core 与 Vanilla Demo，也能查看、完成并保存任务。

- 确定 B42 模组目录、定义加载路径、Lua 核心与 PZ 接口。
- 章节列表、任务详情、基础依赖展示、最多三个任务追踪、中文/英文。
- 手动、技能、物品检测；完成状态保存与重新进入后恢复。
- 一种小额物品奖励，明确领取账本和中断处理。
- 用独立测试档验证，正式存档不作为首轮测试场。

发布门槛：新档/读档、连点领取、满背包、死亡换角色、禁用再启用内容包、错误定义、缺失依赖、1920×1080 与 3840×2160 界面。奖励发放前后强制中断与恢复必须验证。

## v0.2.0：Alpharius 首条主线 alpha

- 约 30–35 个任务串通入住、停水停电准备、运输、远征、供电和供水。
- EPR 优先适配，其次验证房车能力。
- 获取实际设施维修状态和沙盒阈值；避免复制第三方内部材料规则。
- 旧档当前状态补认、手动修复与诊断说明。
- 验证任务系统本身不会改变整合包沙盒参数。

## v0.3.0：内容作者工具 beta

- 可缩放任务图、搜索、任务类型文档、内容导入导出。
- 校验重复 ID、缺失依赖、循环、未知物品和翻译键。
- 导入后预览与验证；可视化编辑器是否内置依据原型成本决定。
- 稳定扩展接口、示例适配器与数据迁移工具。

## v0.4.0：联机实验

- 服务端权威判定和发奖、个人/团队/世界范围规则。
- 并发领取、断线重连、重放请求、加入已有世界与管理员修复。
- 在完成专门测试前始终标记 experimental。

## v1.0.0：维护承诺明确的稳定版

- 固定兼容窗口、稳定数据与存档契约、文档和升级指南。
- Alpharius 完整主线约 50 个任务、专业与生活支线约 40 个任务；数量服从教学质量。
- 至少一轮真实游玩反馈与性能回归，已知问题公开记录。

## 每次发布

1. 离线测试与内容校验通过。
2. 按变更范围执行独立游戏测试，记录游戏/模组版本和限制。
3. 涉及存档则执行升级、降级保护、失败恢复用例。
4. 更新变更记录、兼容矩阵和迁移说明。
5. 以明确白名单构建，只包含本项目文件；核对压缩包内容与校验值。
6. 创建带版本号的源代码与发布包，稳定工坊渠道与测试渠道分离。

## 维护节奏

- 修复数据丢失和阻断进度的问题优先于新任务数量。
- 游戏或关键依赖更新后先在测试环境复核，再更新兼容声明。
- 版本说明区分已验证、待验证和不支持；不把“作者称支持”当成本项目验证。
- 以 GitHub Issues 收集复现步骤，里程碑管理范围，不承诺每周都发功能版。
